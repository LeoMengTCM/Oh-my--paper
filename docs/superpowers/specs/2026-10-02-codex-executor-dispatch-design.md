## 已确认设计

Claude 负责交互、范围确认和验收，Codex 执行用户已授权的研究子任务。选择保存到项目级 `.pipeline/execution.json`，不与研究类型、任务 assignee 或 Codex 原生续行配置混用。选择 Codex 后不得以本机 Claude 子代理代替，不得失败后静默切换。

- setup 分开检查 CLI 就绪状态与选择执行器，保存 `version: 1`、`executor: codex|claude`、`onFailure: stop`。
- 旧项目没有配置时询问一次，不推断；配置损坏时报错。重复 setup 保留配置，显式获准才更改。
- 可安装的共享 skill 内提供统一脚本：读取配置、准备独立运行目录、启动 `codex exec`，保存输入、事件、错误、退出状态与结果。
- 通过 stdin 传任务，不将任务插入 shell 命令，不指定模型，不绕过宿主或 Codex 权限。默认继承 Codex 沙箱配置；需要写权限而环境不允许时报告，不自动提权。
- 每次任务声明实际期望产物。只有进程成功、最终回复有效、期望文件有效且本次生成或更新后才报告执行成功；研究质量仍由 Claude 验收，不自动将任务标为 done。
- 所有 Claude 命令及角色在专业分支之前读取统一路由规则；plan 的研究计划生成也属于执行任务，setup/状态同步/用户决策仍由 Claude 负责。
- SessionStart 恢复执行器选择；Codex 被派发子进程只执行当前任务，不递归派发，不启动全项目续行。
- 更新实际安装副本前核对路径及旧文件，保留备份；不改认证、权限或其他全局设置。
