日期：2026-09-29
状态：PubMed 分批取回、检查点恢复和 SR-02 衔接的核心实现及离线验证完成；真实服务验收未完成。未提交、未推送、未改变版本号。

## 实现

- 保留 query/total_count/returned/results 和候选检索入口，新增明确的完整性、查询参数、执行时间、运行 ID、请求 PMID 与缺项。
- `--all --checkpoint` 固定 PMID 清单后分批获取元数据和摘要；`--resume` 复用成功字段，不重取完整快照与已完成批次。
- 区分文章没有摘要、响应漏掉整条 PMID、XML 结构不完整；不能仅凭元数据条数相等判定完整。
- 本实现 UID 清单上限为 10000；更大查询明确 partial/uid_limit，不自动日期分区，不承诺无限取回。
- 有限重试、单进程节流和 Retry-After；较长等待保留进度后停止。HTTP 200 的错误对象不当成功。
- 检查点使用独占锁、原子写入和请求绑定；参数变更或损坏状态拒绝恢复，不自动重置。Ctrl+C 释放本进程锁，别的进程锁不自动删除。
- 输出默认不覆盖；即使同名文件在请求期间被其他操作创建，也不会未经 --overwrite-output 覆盖。结果文件不得写入检查点内部。
- 请求配置和错误 URL 不保存 API key/email。测试使用明确的空身份或合成身份参数，不访问真实服务。
- SR-02 导入器与记录校验保留来源完整性，拒绝把部分结果提升为 complete；保留日期参数、查询转换和 source_run_id，searched-at 必须对应源执行时间。
- 共享 RCT profile、PubMed skill 文档和阶段映射同步更新。

## 未验证与边界

- 本轮未运行真实课题、未使用账号访问 PubMed、未下载实际文献，也未访问患者数据。
- NCBI 官方文档页触发浏览器验证，搜索服务返回限流。Context7 只取得第三方接口说明，不能替代当前官方服务验证；10000 是本实现保守支持的上限，不是已现场核实的服务承诺。
- 所有 HTTP 行为测试在传输边界使用合成响应；真实 API、代理、跨平台文件系统及大结果集仍需单独验收。
- 新建输出的原子独占发布需要文件系统支持硬链接；不支持时明确报错，不退回不安全覆盖。
- 只完善 PubMed；其他数据库仍使用合法导出或既有工具，不宣称已有统一的全数据库恢复系统。
- 检索完整性不等于数据库范围充分，也不等于全文已取得、研究已纳入或 Meta 分析已完成。
- 没有远端 CI 运行；当前结果为本地检查。
