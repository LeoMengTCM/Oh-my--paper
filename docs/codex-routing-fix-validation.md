# OMP 不按流程执行：修复与回放

日期：2026-09-30。

## 用户报告

两个症状：只做初步检索便推荐肿瘤选题，需要用户提醒先 survey；survey 交付后，
又需用户提醒按 OMP 下一步，而且使用独立的 2–4 候选收敛替代原 OMP 选题流程。
用户项目明确要求：五方向 idea board → 确认评估范围 → idea eval → 最终选题。

## 原因

- 实际启用的个人插件仍为 `1.1.2+codex.20260906064410`，没有 `omp` 总入口。
  上次验证的仓库与临时包可被发现，并不证明用户启用的是该包。
- 总入口直接从请求词选择下游工作流，缺少统一的阶段、依赖和产物检查。
- 原 OMP 的五方向评估流程与 `research-idea-convergence` 的独立 2–4 候选流程
  同时可触发。上次新增入口没有解决这个冲突。
- survey 收尾只要求询问是否进入构思；没有区分“仅做 survey”和“已授权完整流程”。
  项目还出现评估范围已确认，但 execution_context 仍提示再次询问的状态漂移。

上次 140 项测试覆盖安装、记录、统计等软件能力，没有覆盖这些实际模型对话行为。

## 修复

- `skills/omp/scripts/workflow.mjs`：只读检查 brief、兼容任务格式、阶段、依赖、
  产物路径和完成说明，返回当前任务与下一动作；空任务表不当作流程完成。
- `omp/SKILL.md`、生成的 AGENTS.md、Conductor、工作流入口和共享规划/调研技能
  均先核对状态，再选具体工作流。旧项目缺字段先核读和补记，不自动重做调研。
- 标准 OMP ideation 保持五方向生成、范围确认、idea eval、最终选择。
  独立 2–4 收敛仅在用户明确选择轻量流程时使用。恢复时跳过已完成步骤。
- 已授权完整流程中，收尾更新任务与记忆，重新路由并执行下一项工作；实际研究决策
  仍由用户确认。明确的单次任务可以按 standalone 范围执行。
- 已备份并更新实际个人插件及用户项目入口，保留研究数据和任务进度。
  对照任务与 idea_board，将 execution_context 中过期的范围询问改为恢复已确认评估。
- `check-codex-runtime.mjs --installed` 现在检查实际启用状态、会话技能加载器和
  已加载缓存中的 SKILL、路由脚本、ideate 内容，不再只验证源码包的发现能力。

## 验证

全量命令：`OMP_REQUIRE_R=1 npm run check`，使用既有隔离 R 库。
Node 31 项、Python 116 项，合计 **147 项通过，0 失败，0 跳过**。
新增七项覆盖：调研前选题、只有 done 无证据、调研后衔接、旧任务、后期起点、
单次任务范围、空任务和缺失依赖。脚本结果只证明结构条件，不证明研究内容质量。

另运行两次真实 `codex exec` 对话回放，继承本机模型配置，使用隔离临时项目、
明确标记的模拟资料和禁止联网约束。不是替身模型，也不读取真实研究内容。

| 回放 | 模型实际行为 | 产物与轨迹检查 |
|---|---|---|
| 从肿瘤领域选题，但只有三个初查线索 | 先读 omp、运行 workflow，写证据缺口核查与后续检索计划；不推荐最终题目 | survey 保持 review；未创建 idea_board；轨迹包含 omp/SKILL.md 和 workflow.mjs |
| survey 资料已具备，完成核查后继续完整流程 | 同一轮登记 survey 完成，调用 inno-idea-generation，生成五方向，再请求评估范围 | idea_board 有 5 项；scope 与 eval 尚未完成；finalSelection.selectedId 与 confirmation 均为空 |

第二条实际回复停在：“请选择评估范围：全部五个、指定编号，或调整后重新生成”，
并明确确认后才评估，再由用户最终选题。没有停在未执行的“我将进入下一阶段”。

`npm run codex:runtime:check -- --installed` 返回 `installedContentVerified: true`，
确认实际启用缓存匹配当前入口、路由脚本和五方向工作流。插件与项目修改均有本地备份。

这些回放证明本次两种场景已通过，不保证所有开放式对话永不偏离。Hooks 仍受 Codex
信任配置控制，本次未修改信任设置。已有会话可能保留旧指令；应新开一次会话加载
更新后的插件与项目角色。未提交、推送或发布。
