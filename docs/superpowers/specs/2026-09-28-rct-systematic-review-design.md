# 临床优先升级：RCT 系统综述与成对 Meta 分析设计

日期：2026-09-28
状态：产品方向、研究类型范围和完整设计已获用户确认；SR-01 已获准实施。未授权提交、推送、真实研究执行或外部数据上传。

## 1. 目标与非目标

保留通用科研能力及现有 Claude Code / Codex 双插件，以可追溯的临床研究流程作为近期重点。首条示范流程为干预疗效系统综述，以 RCT 为主，支持常规成对 Meta 分析。

成功标准是研究者能核查检索覆盖、筛选决定、研究归并、提取出处与分析结果，而不是自动生成一篇看似完整的论文。

本轮不重建 GUI、不引入数据库或新调度平台、不增加新 track、不默认扩大 agent 数量。不实施网状 Meta、诊断准确性 Meta、IPD Meta。首个自动分析适配器只处理平行组两组比较，RR、MD、SMD；多臂、整群、交叉设计和其他效应量保留记录，但返回需要方法学处理的明确状态，不擅自删除或当作普通两组数据分析。

- `skills/systematic-review/templates/data-extraction.csv:1` 与 `references/meta-analysis-R.md:13-17` 字段不同；后者尚无读取适配器。
- `references/meta-analysis-R.md:14-25` 可选择 RD 却无条件指数转换；偏倚检验条件只写在注释中。

这些是已读取文件中的具体事实，不是完整审计结论。

## 3. 方案选择

### 推荐：现有框架内增加窄范围 profile、结构化产物与校验入口

沿用 `pipeline.track=systematic-review`、现有五阶段、任务状态与文献库。新增专用 profile 和小型脚本，命令只负责解释用户意图、展示判断和调用工具。统计交给 R，确定性数据处理与验证优先使用 Python 标准库。

优点：复用现有能力，能逐段验收，双插件共用规则。代价：需要处理现有任务格式兼容和命令路由。

### 不选：仅补提示词

改动小，但难以保证计数、重复研究识别、字段映射、分析前置条件与中断恢复。

### 不选：新建研究平台

会引入 UI、账户、部署、迁移等独立负担，目前没有必要。

## 4. 流程与阶段映射

五阶段顺序保持不变，不让正式检索早于方案确认：

1. `survey`：探索性检索、已有综述核查、可行性判断；此时的精选阅读不冒充正式筛选。
2. `ideation`：确定 PICO、纳排标准、结局时间窗、检索策略与 SAP，批准版本并记录注册状态。
3. `experiment`：正式检索及导入 → 题录去重 → 题名摘要筛选 → 全文获取与筛选 → 研究归并 → 提取与 RoB 2 → 可合并性判断 → 分析。
4. `publication`：GRADE、Summary of Findings、PRISMA、证据核查与论文。
5. `promotion`：按用户需求准备汇报，不作为研究完成的必要条件。

`/omp:survey` 对 SR 先判定模式：未批准方案时是探索模式；已批准方案时可执行正式检索子任务，该任务归属 experiment。命令名不强行决定任务阶段。新 SR profile 替换旧的“survey 完成正式检索”解释，但不改变非 SR track。

## 5. 人工决定与执行规则

### 5.1 方案和注册

方案版本包含 PICO、资格标准、数据库与检索式、主要/次要结局、时间窗、效应方向、分析人群、合并方法和预设分析。

研究者批准方案后才能正式筛选。注册分别记录 `planned/submitted/registered/not_registered/not_applicable`；未注册必须记录说明并由研究者确认，不能伪造注册号或宣称已前瞻性注册。公开汇总数据综述不机械要求 IRB，特殊数据来源另行判断。

批准记录针对具体版本。资格标准变化会使受影响筛选决定需复核；分析计划变化会使受影响分析失效。不能只把一个 gate 任务标为 done 就认为证据齐全。

### 5.2 筛选与提取

AI 建议、人工独立决定、裁决分别保存。人工 reviewer_id 必须由用户提供或确认，不能由模型虚构。两名 AI 不等于两名研究者。

支持单人研究流程，但明确标注限制，不声称执行双人筛选。不能因无法取得全文而直接判定不符合资格；全文未取得单列。

### 5.3 分析与重跑

确证分析禁止为追求显著性改方法，允许错误修复后的重跑、确定性复现和预设敏感性分析。任何方法变更需批准并记录偏离，探索性结果单独标识。

数据校验通过不代表临床可合并，须另有研究者确认。无法合并是合法结果，输出有依据的叙述性综合。

### 5.4 自动化边界

批量处理已批准的下载、转换、校验与计算；只在方案变化、证据歧义、方法学判断和外部权限问题上暂停。

入口校验防止受支持命令误推进，不宣称能阻止用户绕过工具直接修改文件或运行任意 R 脚本。现有 PostToolUse hook 继续作为提醒，不包装为强制执行控制。

## 6. 数据规范

新增产物位于 `.pipeline/systematic-review/`，每个结构化文件声明 `schema_version`。继续复用 `.pipeline/docs/protocol.md`、`sap.md` 与 `.pipeline/memory/protocol_deviations.md`；不另存可独立编辑的重复正文。

原始检索响应、PDF、OCR 和题录仍在 `.pipeline/literature/<corpus>/`；现有 `metadata.json`、引用键和 `refs/references.bib` 不重算、不搬迁。

### 6.1 实体边界

- `record_id`：一次来源检索或导入的题录记录，保留 source 和 search_run_id。
- `report_id`：一份实际报告；多个数据库记录可能指向同一报告。
- `study_id`：一次研究；多份论文或注册记录可能属于同一研究。
- `arm_id`：研究内的研究组。
- `outcome_id`、`timepoint_id`、`analysis_population`：预设结局、时间窗与分析人群。
- `analysis_id`：方案版本下的比较、结局、时间窗、分析人群与效应量组合。

ID 一经分配保持稳定，不依赖可变标题或引用键。去重报告不等于合并研究；相似标题只提示人工核查，不能自动删掉可能不同的试验。

### 6.2 最小产物集

| 文件 | 权威内容 |
|---|---|
| `review.json` | profile、方案版本、检索模式、注册状态、研究者角色 |
| `approvals.jsonl` | 批准对象及版本、批准者、时间、说明与替代关系 |
| `search_runs.jsonl` | 数据源、原始检索式、日期范围、排序、执行时间、命中/取回数、完成状态、原始结果路径 |
| `records.jsonl` | 原始题录索引及其 report_id 映射、去重依据 |
| `reports.jsonl` | 报告身份、外部标识、现有文献目录、全文获取状态 |
| `studies.jsonl` | 研究身份、设计、注册号及报告归并依据 |
| `screening_decisions.jsonl` | 报告、筛选阶段、reviewer、人工/AI来源、决定、理由、方案版本与裁决 |
| `extractions.jsonl` | 研究/组/结局/时间点/人群对应的提取值、单位、缺失类型与出处 |
| `rob2.jsonl` | 具体结果的偏倚评价、工具版本、信号问题依据与人工确认 |
| `analyses/<run_id>/` | 输入快照、运行清单、结果表、R session 信息及图表 |
| `summary_of_findings.json` | 按比较与结局记录 GRADE、降级理由、绝对与相对效应来源 |

CSV 仅作为人工编辑/交换格式，不再维护第二套独立权威数据。导入必须验证并预览变更；Markdown 进度、PRISMA 计数和展示表从结构化记录生成。

### 6.3 提取出处

每个关键数值至少关联 report_id、页码或表/图/章节定位及原文摘录；注册网页使用 URL、访问日期和字段位置。保留原始值、标准化值和转换规则，不覆盖原文。

区分“未报告”“不适用”“无法提取”和真正的 0。OCR 文本不能单独证明数值无误，关键统计值需要原文核对。

### 6.4 状态与版本

继续使用现有任务状态 `pending/in-progress/review/done/deferred/cancelled`。产物状态另行使用 `draft/needs_review/validated/superseded`，运行状态使用 `running/partial/failed/completed`，三者不混用。

任务规范以顶层 `tasks` 和 `dependencies` 为目标。先检查所有读写方；兼容导入 `master.tasks`、`dependsOn`，不得静默覆盖已有工程。两种结构并存且冲突时停止并列出冲突，不猜测权威版本；不强制改写现有 task ID。

## 7. 检索与恢复

正式检索必须记录完整性，不设默认精选上限；若设置人为上限则状态为 partial，不能标为完整检索。

PubMed 分批获取与恢复必须尊重 API 实际上限；超出服务可取回范围时使用经官方文档确认的分区策略或用户导出，不假定单纯 retstart 翻页能取回任意数量。

保存请求参数、运行时间、返回 ID 和批次完成状态；摘要或元数据缺失不能静默丢弃 PMID。请求失败采用有限重试，日志不得输出 API key。重试复用成功批次，不对已确认记录重复计数。

导入首先支持 PubMed 现有 JSON、RIS 和规范化 CSV；具体数据库字段差异通过 fixture 检查。导入不等于证明检索覆盖完整，检索日志缺信息则显式待补。

不自动联网搜索、不调用付费 OCR、不替用户注册或上传研究材料；这些操作按任务授权执行。

## 8. 分析适配器边界

R 读取经过校验的长表与批准的分析配置，不在脚本内部猜字段、挑时间点或合并不同结局。

分析前检查：事件数为合法整数且不大于对应 n；n 为正；均值/SD/方差有效；单位与效应方向兼容；比较不混人群；同一 analysis_id 不重复使用同一研究参与者。

首版 RR、MD、SMD 的零事件处理、方差估计和区间方法必须在 SAP 中明确并进入运行清单。没有策略时停止对应分析，不能静默加连续性校正。双零事件和无法估计方差的记录保留并解释处理，不从综述中删除。

仅有一个研究时展示单项效应，不伪造合并异质性。研究不足、模型不收敛或不支持的设计输出具体原因。

RR 的内部对数尺度与输出比值尺度分开；MD/SMD 不执行指数转换。RD 现有示例修正尺度错误，但不因此扩展首版适配器支持范围。

不默认执行 Egger 检验：独立研究数少于 10 不执行；达到 10 也须满足预设方法及效应量适用性，尤其不能把二分类结局和 SMD 一律套同一检验。漏斗图不被描述为发表偏倚的确定证明。

森林图、结果表与正文数字均来自同一运行结果。图形脚本允许 `.R`，不强制改名为 `.py`。制作图形前遵循项目可用的 dataviz 指导。

## 9. 验收设计

### A. 离线确定性测试（每次 CI）

- 同一报告跨来源出现，只计一次筛选对象，但保留来源数。
- 同一研究多份报告，不重复计入合并分析；主要/随访报告仍可贡献不同时间点证据。
- 筛选分歧不能自动变为最终纳入；AI 不能生成虚构人工确认。
- PRISMA 在完成流程中核对 records/reports/studies 三种单位；未完成时显示 pending，不强行凑平。
- 全文无法获取单列，不计为资格排除。
- 新方案版本不会沿用已失效的批准；没有注册号但有如实说明的流程不会被伪装为已注册。
- 事件数越界、缺失当 0、单位不符、重复比较与不支持设计明确失败。
- 旧任务格式可读取；冲突结构失败；非 SR track 不受影响。
- 中断批次恢复后不遗漏、不重复；API 日志不泄露凭证。

### B. 统计参考测试（有 R 的专用 CI）

用明确标注的合成数据覆盖 RR/MD/SMD、效应方向、零事件、单研究、少量研究和模型失败。预期值来自手算的单项效应与独立复核的固定参考结果，不在同一测试中用被测函数生成预期值。

预先规定绝对/相对数值容差，记录 R 和统计包版本。无 R 时本地清楚报告跳过；正式发布需要有 R 环境通过，不以跳过当成功。

### C. 公开案例验收（另行执行）

选择数据与全文可合法获取、可核查的已发表 RCT 成对 Meta 案例；比较纳入研究映射、提取值、效应方向和合并结果。发现差异追溯方法与数据，不为了匹配论文结果修改数据。

本设计没有选定或宣称验证过任何真实案例；选题检索、许可核查与真实运行属于后续单独验收任务。合成测试不能替代此项。

## 10. 实施拆分

不把整套升级作为一次大改动。以下子项目各自形成详细计划、实现与验收：

1. **SR-01 规则与入口修复**：共享 RCT profile、SR 双模式路由、正确阶段映射、注册/伦理/重跑边界、任务格式兼容约定、现有 R 示例明显错误及双插件一致性测试。保留旧非 SR 流程。此阶段不宣称实现全自动综述。
2. **SR-02 记录与筛选**：结构化规范、导入/去重、批准与筛选校验、PRISMA 计数；离线 fixtures 先行。
3. **SR-03 正式检索与恢复**：PubMed 完整性、分批/限额、恢复和日志；外部接口先核对官方文档，再进行受控真实验收。
4. **SR-04 提取与分析**：研究—报告映射、带出处长表、RoB 2/SoF 产物及 R 适配器；统计 CI。
5. **SR-05 写作与公开案例**：以已确认产物生成报告、注册/方法陈述核查、公开案例端到端验收。

CNKI 复用代码许可核查作为并行维护事项，未解决前不能声称来源授权完备；不把它混入 Meta 统计实现。

## 11. 验证与发布纪律

继续执行 `npm run check`，新增确定性测试后接入现有 CI。Claude/Codex 入口都引用同一 profile，静态一致性检查增加 SR 分支关键概念，但静态通过不替代行为测试。

用户项目旧数据不自动重写，迁移先预览并保留备份。新字段采用可选扩展和显式 schema 版本，不破坏原有引用键。

版本号、提交和推送在实际实施及验收后另行处理；未经要求不提交，不向 upstream 推送。

## 12. 自审结论

- 产品方向批准与具体实施批准已区分。
- 首版自动分析范围明确，不承诺覆盖所有 RCT 设计。
- 五阶段顺序与方案先于正式筛选的关系已明确。
- 注册、伦理与可复现性表述不机械套用。
- 权威数据、派生摘要、任务状态与运行状态已分开。
- 自动执行检查的能力边界明确，不把提示式 hook 说成安全隔离。
- 测试数据与真实研究证据明确区分。
- 完整设计已获批准；先实施并验收 SR-01，不把全部子项目一次实现。
