## 范围

先完善现有 `skills/pubmed-search/scripts/pubmed_search.py`，不新增外部依赖，不运行真实课题检索。不实现未经核实的自动日期分区；不把 History Server 或增加 retmax 当作无限制全量检索方案。

## 接口

- 默认 `--retmax 20`：探索性候选检索；按用户上限取回成功时仍退出 0，但输出明确 partial/bounded_search，不能作为完整综述检索。
- `--all --checkpoint <目录>`：明确请求完整取回。首版支持的 ESearch UID 清单上限保守设为 10000；超过上限输出 partial/uid_limit，停止批量元数据获取，提示完整导出或人工审核的拆分。
- `--batch-size`：默认 200，允许 1–200，避免巨大的 UID 请求。
- `--resume --checkpoint <目录>`：读取相同查询参数和 PMID 快照，只补取缺失元数据/摘要；查询、日期、模式或批大小改变时拒绝混用。
- `--abstracts`、日期参数、sort、output、email、api-key 保留。支持环境变量提供 API key，不把 key/email 写入检查点或错误日志。
- 输出已有文件默认保护；显式 `--overwrite-output` 才替换。输出不能位于检查点内部，避免覆盖状态文件。

## 结构

- API 模块：有限重试、请求间隔、结构化错误、ESearch/ESummary/EFetch 解析；UID 列表请求使用 POST。
- 检查点模块：请求规范、运行 ID、搜索快照、每批缓存，原子替换与独占锁。不自动删除其他进程的锁，不迁移未知格式目录。
- 运行模块：保存 UID 快照，再分批取回；允许复用已成功的元数据与摘要；完成度由实际缓存计算，不信任“已完成”标记。
- CLI：保持既有字段并新增完整性说明；错误不泄露请求 URL 中的凭证。

## 完成与失败

完整取回意味着完整 UID 清单、所有目标元数据以及请求的摘要响应均取得。真实文章没有摘要与响应缺少整条 PMID 不同，前者可完成，后者必须报告缺项。

网络失败保存已有成功项后停止；恢复不重查已固定的完整 UID 清单。无摘要请求时不为缺摘要报错。HTTP 200 中的错误对象也不得当作成功。

退出 0：所请求工作成功，完整性仍以输出字段判断；有意的候选上限可为 partial。
退出 2：请求工作不完整、达到支持上限或中断。
退出 1：参数、输出冲突、检查点损坏或不兼容。
