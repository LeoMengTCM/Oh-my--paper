## 已实现

- `review_state.py validate/prisma`：加载 review、批准、检索、来源题录、报告、研究与筛选决定；只读校验并输出 JSON 或 Markdown。
- 每个报告的人工独立判断、AI 建议、裁决分别处理；single/dual 明确区分。AI 不计入独立筛选人数，不能裁决。
- 版本批准、显式 supersedes 修订、resolves 裁决引用；检测重复、分叉和循环。旧判断修订使相关裁决失效，晚于全文筛选的题名摘要修订使旧全文判断待复核。
- 区分来源 records、报告 reports 与研究 studies。保留重复来源题录，精确识别报告，不把同一 RCT 的多份报告算作多个研究。
- PRISMA 计数区分待筛选、待获取、未取得全文、全文排除和待归并；检查各步骤数量关系。定量合成研究数保留 null，不假装已做分析。
- `import_records.py`：PubMed JSON、RIS、CSV 的只读预览；DOI/PMID 归一化；复用既有 report_id；多标识冲突停止。未知命中数为 null，默认 partial，完整标志需要明确匹配的总数。
- 两条 CLI 均不写回用户研究文件。重复 JSON 字段与损坏输入明确报错，不用空结果掩盖问题。
- 增加字段规范、合成可运行示例，并更新共享 profile 和 skill 入口；自动记录写回、迁移、界面、身份认证不在本轮范围。
- npm/CI 接入 Python 标准库测试；本地 Python 可由 PYTHON 环境变量指定。

## 真实使用边界

- 程序验证记录结构和关系，不证明人类确实独立筛选或批准，也不检查实际 PDF 是否被阅读。
- 批准文档检查存在性，不做语义核验或签名验证；修改方案正文须同步更新版本。
- validate 的退出 2 表示记录不完整，并非所有任务都不能继续。需要根据具体 blocker 执行筛选、裁决或补录；缺少方案批准才阻止依赖批准的工作。
- 退出 0 仅表示本工具覆盖的检索/筛选/归并记录完整，不证明检索范围充分，不表示整项综述、RoB 2、GRADE 或统计完成。
- 导入先输出预览，须人工核查再维护权威 JSONL；尚无事务写入或自动迁移。不要并发修改记录后把混合状态作为最终结果。
- 尚未进行真实账号、数据库、全文资料或真实多人筛选验收；没有远端 CI 运行。
